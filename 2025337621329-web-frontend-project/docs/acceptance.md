# acceptance.md 验收标准

> 验证证据：页面截图、Network面板查看请求URL、status code、response返回JSON。

## 功能1：列表与搜索 ——订单列表
1. 正常场景
- 操作：登录进入订单列表页
- 预期：网络请求成功，渲染多条订单卡片，展示订单号、商品、桶数、状态、下单时间
- 证据：Network查看`/api/order/my‑list`，status 200，response返回订单数组。

2. 空场景
- 操作：登录账号，没有任何历史订单
- 预期：页面展示空状态提示文字“暂无订单，快去下单吧”，页面不报错。
- 证据：Network接口返回空数组[]。

3. 失败/错误场景
- 操作：模拟接口500服务器错误
- 预期：页面展示“订单加载失败，请稍后重试”提示。
- 证据：Network看到status 500，查看response中的message。

## 功能2：详情 ——订单详情
1. 正常场景
- 操作：点击列表中订单，进入详情
- 预期：完整展示订单编号、商品、寝室地址、桶数、状态、下单时间
- 证据：Network `/api/order/detail` status200，response包含完整order对象。

2. 边界场景：传入不存在orderId
- 预期：页面提示“该订单不存在”

3. 错误场景：接口请求异常
- 预期：展示详情加载失败提示

## 功能3：表单 ——订水提交表单（登录+下单）
1. 登录正常场景
- 操作：输入正确模拟账号密码点击登录
- 预期：登录成功，跳转商品下单页面
- 证据：Network `/api/user/login` status200，返回用户信息data。

2. 登录错误边界：账号密码错误
- 预期：页面展示账号密码错误提示，不跳转。

3. 下单表单正常提交
- 操作：选商品，填完整楼栋寝室号桶数，提交
- 预期：提交成功，生成订单，跳转到订单列表。
- 证据：Network看到`/api/order/create` POST请求，status200，response返回orderId。

4. 表单空校验（边界）
- 操作：楼栋、寝室号、桶数留空直接提交
- 预期：页面本地校验，提示必填项不能为空，不发送网络请求。

5. 提交接口报错
- 操作：模拟接口返回500
- 预期：页面提示订单提交失败，请稍后重试。
